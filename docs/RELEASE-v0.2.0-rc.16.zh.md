# ContainerCacheGuard 0.2.0-rc.16 候选版

针对“累计查询很大、驻留命中很少、可见普通缓存仍大”的证据缺口增加覆盖归因，并支持明确授权的数据文件覆盖与受保护的压力加速。

- `coverage_audit`：按根目录和文件名类型统计元数据/打开/跳过/初查/复查/驻留/合格范围/建议及区域变化；展示PGDATA环境线索、根设备/inode/UID/权限和挂载位置。
- auto增加`executable_data_paths`，只对显式数据根下的授权路径放开执行位规则；不增加根、不追链接、不取消排除与库文件规则。大文件改为按区域轮转。
- 扫描历史有界，区分窗口内新查询和重复查询，淘汰明确计数。累计查询不是唯一全量覆盖，驻留与策略合格均不等于证明冷页或干净页。
- 候选ID关联创建、建议、立即/延迟复查、重新驻留保护、重试、退避和终态；额外复查可配置为建议后30/120秒等时点。事件环有界，覆盖掉的事件计数，不假装保存全部逐候选历史。
- `pressure_boost`显式启用，在已有真实保护允许时于自身/父级高水位或节点预警带加速至配置建议上限。复用`critical_mode=bounded`和持续健康恢复；新OOM、脏页、IO/PSI、refault、业务或节点停止线仍优先暂停，不无上限强刷。
- `guard_transition`记录每次采样到的决策变化，不受周期状态日志一秒节流；它不补造采样间瞬态。

不修改CPU、DBS/HISDBS内存或IO配额，不清理anon/shmem/slab，不重启归零或全局drop_caches。没有证据将slab下降记为CCG收益。用户06:14—07:13的rc.12结论保留为外部证据，现场原因仍需原始日志、实际PGDATA/权限与记账对照确认。

计划与完整参数见[开发计划](RC16-PLAN.zh.md)和[使用手册](RC16-USAGE.zh.md)。发布前需原生双架构回归与>=1GiB隔离对照；实际结果由发布附件和最终交付单记录，不能将隔离PG14探针替代DBS/HISDBS真实备份恢复和48小时验收。
