# rc.14：先检查配置，再看信号为什么暂停

本版保持rc.13的范围和严格默认；不会自动部署到94/171，不放开源PGDATA或强制清理匿名内存。受限输出仍是实验功能。

## 新命令：离线检查

```sh
containercacheguard check-config --config /etc/ccg/output.json
```

只读取配置并验证参数关系，**不读取PGDATA、cgroup或节点/业务信号，不启动扫描和日志进程**。退出0表示配置合法，不代表权限、挂载、信号就绪或业务安全；下一步仍执行`doctor --require-ready`。错误配置返回非零。旧doctor/run/status命令不变。

## 状态和日志新增signals

`signals.node`和`signals.business`各有state、age_seconds、remaining_seconds、error。state为disabled（未配置）、unavailable（无可解释样本）、invalid（输入错误）、stale（过期）、future（未来超过容许值）或ready。年龄/剩余时间单位秒，未知是null，过期剩余值为负；它们只解释该信号，不代表所有保护通过。

节点信号有效时还提供`node_stop_bytes=max(hard,soft)+安全余量`和`node_headroom_above_stop_bytes=available-stop`；等于0说明碰到停止线，负数说明低于停止线，null说明未知。它不是物理机总剩余内存。信号缺项及错误来源绝不会产生可用余量数值。doctor也输出同一结构。

## 输入兼容与加固

节点、清单、业务信号必须是实际普通文件，路径每个组成部分不能为符号链接；FIFO、目录、设备均拒绝。节点/业务16KiB上限包含尾部空白和并发增长；JSON拒绝重复字段（包括大小写/Unicode折叠别名）、顶层非对象和超过32层嵌套。业务信号继续接受其它合法附加字段，节点/清单继续拒绝未知字段。

部署时将信号**目录整体只读挂载**，采集器以原子替换更新；禁止用符号链接或单文件subPath跳转。此前用符号链接的业务信号需要改成真实路径，此收紧是有意行为。受限策略其它参数、可选采集器和四角色绑定见[rc.13手册](RC13-USAGE.zh.md)。

## 到期就停止新建议

每次采样、日志/状态写入前先撤销许可，完成后只在指标和所有启用信号都未到期时重新发放。每个调度tick再次检查最早到期点；出现过期会撤销许可，工作线程在现有安全检查点退让。它不能中断已经阻塞的内核调用，也不会自动停止外部备份。风险后仍等待配置的连续健康窗口，不能用剩余时间显示绕过恢复门槛。

每日一文件、30天/1GB、无Web及静态双架构继续保留。新字段不改变已有可选保护的0值兼容语义；回退须用旧配置和旧程序一起恢复。
