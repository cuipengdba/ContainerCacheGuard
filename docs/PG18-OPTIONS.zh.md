# PostgreSQL 18 pg_basebackup 参数说明

本表按 [PG18 官方文档](https://www.postgresql.org/docs/18/app-pgbasebackup.html) 和 18.6 源码选项表整理。包装器保留原始参数交给内置上游解析器；下表解释选择方法，不能替代上游对组合合法性的检查。正式完整功能矩阵尚在测试，不把“扫描器接受”写成“全部场景已验收”。

## 备份内容与存储

| 参数 | 作用与默认行为 | 怎么用、需要注意什么 |
| --- | --- | --- |
| `-D, --pgdata=目录` | 客户端输出目录；client target 通常必填。 | 在配置仓库下选择不存在或为空的目录。tar 的 `-D -` 为标准输出；该模式需显式选其他缓存策略。 |
| `-F, --format=plain\|tar` | 默认 plain；可简写 p/t。 | 推荐 plain：可直接校验、增量合并，不增加解包等待。tar 有利于传输归档，但恢复前需解包并另行完整验证。 |
| `-i, --incremental=清单文件` | 请求原生增量，默认全量。 | 传前一次备份的 manifest，需同实例及保留的 WAL 汇总。恢复时需要完整父链。 |
| `-c, --checkpoint=spread\|fast` | 控制备份开始检查点，默认 spread。 | fast 缩短等待但可能增加短时业务 IO。包装器保留选择，不把传输限速当检查点限速。 |
| `-r, --max-rate=数值` | 原生传输上限，单位默认 KiB/s，可后缀 k 或 M；32 KiB/s～1 GiB/s。 | 如 `20M`。包装器以配置读写上限和本项的最小值执行，并记录有效值。WAL/协议与实际设备 IO 另测。 |
| `-t, --target=目标[:详情]` | 默认 client；可有 server 或 blackhole 等上游支持目标。 | server 写入发生在数据库服务端，客户端缓存控制不能覆盖那段落盘。`preserve-hot` 会拒绝非 client 输出。 |
| `-T, --tablespace-mapping=旧路径=新路径` | 将外部表空间写到新位置，可重复。 | 两边用绝对路径，路径内 `=` 用 `\=`。目标必须通过路径保护。当前源端 preserve-hot 不支持外部表空间；不能直接据此宣称其恢复链已全面覆盖。 |
| `--waldir=目录` | plain 模式把 WAL 放到指定位置。 | 只在上游允许的模式使用。路径必须独立且可写；当前 preserve-hot 要求默认 WAL 布局。 |
| `-X, --wal-method=none\|fetch\|stream` | 默认 stream，可简写 n/f/s。 | stream 并行接收 WAL；fetch 结束时获取，需保证所需 WAL 未被回收；none 需要独立 WAL 来源。none 的自动校验不会被标为 WAL 完整验证。 |
| `-R, --write-recovery-conf` | 写 standby.signal 及连接配置。 | 用于建立备用库；普通灾难恢复演练是否需要这些文件要单独设计，避免误连原主库。 |
| `-l, --label=文本` | 备份标签，默认上游标签。 | 便于查日志；不要在标签里放密码或业务敏感数据。 |

## 压缩与校验清单

| 参数 | 作用与默认行为 | 怎么选 |
| --- | --- | --- |
| `-z, --gzip` | tar 的 gzip 压缩快捷项。 | 受上游格式/WAL 组合限制。减少容量和传输，但增加 CPU 和解压恢复时间。 |
| `-Z, --compress=算法[:详情]` | 选择 none/gzip/lz4/zstd 等，以及 client/server 位置和级别；默认不压缩。 | 当前内置客户端已编译 gzip/lz4/zstd。服务端压缩仍取决于服务端构建。源端进度观察不直接覆盖压缩 tar。 |
| `--no-manifest` | 不生成备份清单。 | 原生可用，但不能用于本工具默认的完整自动校验或作为增量父清单；结果标为未完整验证。 |
| `--manifest-force-encode` | 将清单路径统一编码。 | 处理特殊文件名时使用；不改变数据内容，也不减少目录/文件数量。 |
| `--manifest-checksums=算法` | 默认 CRC32C；上游允许 NONE、CRC32C、SHA224/256/384/512。 | 推荐完整性要求高时使用 SHA256；NONE 不能产生完整文件校验结果。改变算法会增加不同程度的 CPU 开销。 |
| `--no-verify-checksums` | 不在服务端备份读取时检查数据库页校验和。 | 不等于不生成 manifest，也不等于客户端文件校验。即便文件 SHA 一致，也可能只是完整保存了已有坏页，应谨慎使用。 |

## WAL 槽与连接

| 参数 | 作用与默认行为 | 怎么选 |
| --- | --- | --- |
| `-C, --create-slot` | 创建指定的物理复制槽。 | 配合 slot 与 stream，账号需相应权限；失败或废弃槽若不清理可能造成 WAL 持续保留。 |
| `-S, --slot=名称` | 指定接收 WAL 使用的槽。 | 永久槽生命周期由部署管理；不能认为工具退出会自动删除用户槽。 |
| `--no-slot` | 不创建临时复制槽。 | 用于上游允许的 stream 组合，需要自行保证 WAL 可用；不能随意与 fetch 混用。 |
| `-d, --dbname=连接字符串` | libpq 连接字符串，可含 service 等参数。 | 实际解析后仍核对共享 Socket、端口、PG18 版本与系统标识。不要把密码写进命令行、进程列表或报告。 |
| `-h, --host=地址或目录` | PostgreSQL 连接位置。 | 当前使用配置的共享 Unix Socket 目录；TCP 无法满足当前跨容器源文件身份约束，不予默认为已覆盖。 |
| `-p, --port=端口` | 连接端口，默认来自配置。 | 必须与当前所挂实例匹配。 |
| `-U, --username=账号` | 连接用户，默认来自配置。 | 可使用复制专用角色。目录访问 UID 与数据库 SQL 账号是两种身份，不要混淆。 |
| `-w, --no-password` | 不提示密码。 | 自动任务建议使用，配合安全的 libpq 认证配置；认证缺失应失败，不应无限等待。 |
| `-W, --password` | 在连接前要求输入密码。 | 包装器把标准输入传给原生工具；自动程序需有明确输入机制，不要把密码拼进 shell。 |
| `-s, --status-interval=秒` | WAL 接收状态更新间隔，默认上游值 10 秒。 | 是复制反馈周期，不是本工具的内存采样周期，也不是备份限速窗口。 |

## 运行、同步及帮助

| 参数 | 作用与默认行为 | 注意事项 |
| --- | --- | --- |
| `-n, --no-clean` | 错误后保留上游创建的部分输出。 | 适合排查；残留目录不能当完整备份，重新运行要使用新目录或按失败流程处理。 |
| `-N, --no-sync` | 跳过上游最终同步。 | 会降低上游的持久化保障。缓存策略的窗口写回仍可能发生，不能用它证明整个工具从不 flush。 |
| `--sync-method=fsync\|syncfs` | 选择上游最终文件同步方式。 | syncfs 的文件系统范围可能更大，和同机业务共享设备时需要观测代价。 |
| `--no-estimate-size` | 不先估算备份大小。 | 大量文件时可降低估算工作，但与 `--progress` 不兼容，上游会报错。 |
| `-P, --progress` | 显示原生进度。 | 初始估算可能花时间；显示完成不是自动证明后续 WAL/校验成功。 |
| `-v, --verbose` | 输出上游详细信息。 | 与包装器结构化 stderr 日志并存；收集日志时不应误认为所有行都是 JSON。 |
| `-V, --version` | 显示内置 pg_basebackup 版本。 | `pgcacheguard --version` 是包装器版本；两者应分别记录。 |
| `-?, --help` | 显示内置原生帮助。 | `pgcacheguard basebackup --help` 不需要配置数据库即可查看。 |

## 参数兼容与缓存覆盖对照

| 模式 | 原生参数传递 | 客户端输出缓存 | 源 PGDATA 缓存 | 自动完整校验 |
| --- | --- | --- | --- | --- |
| 默认表空间、plain/client、默认 WAL、manifest 和 WAL 完整 | 保留 | preserve-hot / destination-only | preserve-hot | 文件及 WAL 检查成功后为 true |
| 原生增量 plain | 保留 | 同上 | 解析变化块映射；同样受 UID/共享卷条件限制 | 校验增量文件与 WAL；可恢复还需正确父链 |
| tar / 压缩 tar | 保留，需显式换策略 | 受控的客户端普通输出文件可处理 | 当前不覆盖 | 需解包并补做验证，不能自动记为 true |
| 标准输出 tar | 保留，需显式换策略 | 管道本身不属于本地备份文件；下游写入不在工具控制内 | 当前不覆盖 | 下游归档后另做 |
| server / blackhole target | 保留，需显式换策略 | 不覆盖服务端文件写入 | 当前不覆盖 | 当前不自动完成 |
| 外部表空间 / 另置 WAL | 原生支持条件内保留，需显式换策略 | 只覆盖经路径保护登记的实际客户端目标；完整矩阵仍待验证 | 当前不覆盖 | 按实际清单、WAL 和映射条件验证 |
| 无 manifest / manifest NONE / WAL none | 保留 | 取决于格式与策略 | 符合普通目录条件时可处理 | 缺少的那部分不能标为已完整验证 |

工具不会为了让这些模式“看起来都受保护”而默默改成另一种备份格式、强制快检查点或补回用户关闭的清单。生产推荐明确选择推荐模式；对其他模式应接受其控制边界，或者先补齐实现与测试后再启用。
