# 需求、任务与版本变化

## 2026-11-06：通用容器缓存治理

项目从原 PostgreSQL 专用备份原型转为 ContainerCacheGuard。当前产品树已替换，Git 历史保留，不继续打包 PG 客户端或接管恢复。明确支持 auto 自动发现与 paths 指定范围，observe/enforce 独立控制动作。

| 工作 | 状态 |
| --- | --- |
| 独立前台常驻程序、静态双架构构建 | 已实现，验证中 |
| 两种范围模式、严格参数校验、中文帮助 | 已实现 |
| cgroup v1/v2读指标、文件安全、有界发现和区域治理 | 已实现；各环境能力需实测 |
| 压力保护、暂停恢复、业务信号、净变化/再次驻留记录 | 已实现，集成测试中 |
| 中文说明、配置、部署、设计、构建与测试文档 | 已提供并随实测更新 |
| 真实约198GiB迁移数据对照与模拟压力 | 进行中 |
| GitHub原生双架构CI与候选版发布 | 进行中 |
| 真实Kubernetes/OpenShift与72小时长稳 | 待完成，不能由容器实验替代 |
| 约5分钟问题分析与约10分钟设计/测试普通话视频 | 待新方案测试结论稳定后制作 |
| 有界目录级 inotify 访问提示 | 已实现，保护与反馈不被提示绕过 |
| cachestat、内核定向回收与应用缓存插件 | 后续评估，不属于当前已实现能力 |

“其它缓存”的当前范围是监测与解释，不能强制清空应用堆。新增后端必须说明作用对象、权限、回写和业务影响，并有独立验证；不会用全机 drop_caches 作为快捷实现。
