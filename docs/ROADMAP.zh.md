# 需求、任务与版本变化

## 2026-11-11：下一版本开发至发布

按用户要求开发rc.12：严格能力预检、等待重扫索引调度、重复无效回收退避、无Web离线小时统计和四角色配置。原生两架构回归与附件核验结果据实写入[交付记录](RC12-DELIVERY.zh.md)，用法见[完整手册](RC12-USAGE.zh.md)。不自动启用PSI、不替换94或修改171；无PSI兼容策略与真实业务48小时仍未交付。

## 2026-11-10：取消Web页面和HTTP服务

用户要求不再提供Web资源页面，改为详细日志。rc.11移除页面、API、Prometheus和健康HTTP端点，不监听端口；旧Web参数仅兼容读取并提示已停用，新配置省略它们。详细日志增加中文原因、可读单位摘要、间隔计数变化及错误，保持有界频率和30天/1GB清理。历史Web实测保留时间背景，不代表新版仍提供页面；48小时/外部小时图表需求保留。rc.11已公开预发布，两架构各56项race顶层单测和24项CLI通过，详见[交付记录](RC11-DELIVERY.zh.md)。

## 2026-11-10：每日日志与自动清理

用户新增运行打印日志、一天一个文件、最多30天或总量超过1GB自动清理。rc.10已实现并发布双架构静态候选，补充保护输入缺失时暂停回收。清理先删最旧历史，当天单文件触顶则截断当天旧内容；控制台仍输出，目录及阈值可配。功能回归、短时现场检查和未验证项见[本版交付](RC10-DELIVERY.zh.md)及[日志手册](LOGGING.zh.md)，不提前认定现场已升级或业务稳定。

## 2026-11-10：后续两个版本

[两版本计划与验收](NEXT-TWO-VERSIONS.zh.md)：rc.8先完善连续健康等待与异常检查，rc.9再增加低开销Prometheus及健康/就绪入口；两版独立回归、独立预发布。误发的CRG磁盘标定要求不纳入CCG。

## 2026-11-10：继续开发与GitHub发布

按用户要求继续版本开发。本轮0.2.0-rc.7针对大量文件下的新目录事件饥饿增加独立额度与有界重试；补充refault未知状态、只读诊断解释和网页空窗处理。配置保持兼容，原生amd64/arm64单测、race、CLI及静态检查结果随候选发布。未修改171，也未用小文件回归代替真实数据48小时验收。详见[版本说明](RELEASE-v0.2.0-rc.7.zh.md)。

## 2026-11-06：通用容器缓存治理

项目从原 PostgreSQL 专用备份原型转为 ContainerCacheGuard。当前产品树已替换，Git 历史保留，不继续打包 PG 客户端或接管恢复。明确支持 auto 自动发现与 paths 指定范围，observe/enforce 独立控制动作。

## 2026-11-07：四容器、Web 和 48 小时验证

新增内置只读 Web 页面，展示 cgroup 内存分类、IO、OOM 和策略状态；默认关闭并只推荐回环监听。新增 [四容器部署说明](FOUR-CONTAINERS.zh.md)：DBS/HISDBS 业务容器各有独立备份容器，源端与输出端分别监控。早期曾用PG18副本做隔离实验；**2026-11-08的现行目标已改为PG14.19**，94的DBS/HISDBS已迁入11月8日的真实PG14数据，并有两个尚未注册到YsP的临时备份Pod。48小时连续压力、两轮03:00全量备份和四容器正式接入尚未完成，不能提前标记通过。94节点约30GiB内存，源171约61GiB，差异必须列入结果。

## 2026-11-07：当前交付范围调整

用户决定暂不生成新版说明视频，也暂不制作给领导的长期方案；只有收到后续明确通知才重新安排。旧候选版已发布的视频和历史文件保留，不能代表当前48小时试验的最终结论。四容器实测、每12小时图表、实时Web、源码、二进制和使用文档继续进行。

隔离实验初次尝试用节点IP直接访问Web失败：页面默认只绑定Pod内回环地址，节点没有转发端口。实验已增加仅绑定测试节点内网地址的四路临时转发，并在保持observe动作时让四处实际进程使用修复时钟误报的rc.2；页面和状态API从客户端均返回200，四Pod无重启。正式部署的访问控制与端口方案见[四容器部署说明](FOUR-CONTAINERS.zh.md)。
