# 需求、任务与版本变化

## 2026-11-06：通用容器缓存治理

项目从原 PostgreSQL 专用备份原型转为 ContainerCacheGuard。当前产品树已替换，Git 历史保留，不继续打包 PG 客户端或接管恢复。明确支持 auto 自动发现与 paths 指定范围，observe/enforce 独立控制动作。

“其它缓存”的当前范围是监测与解释，不能强制清空应用堆。新增后端必须说明作用对象、权限、回写和业务影响，并有独立验证；不会用全机 drop_caches 作为快捷实现。

## 2026-11-07：四容器、Web 和 48 小时验证

新增内置只读 Web 页面，展示 cgroup 内存分类、IO、OOM 和策略状态；默认关闭并只推荐回环监听。新增 [四容器部署说明](FOUR-CONTAINERS.zh.md)：DBS/HISDBS 业务容器各有独立备份容器，源端与输出端分别监控。94 的隔离 K3s 测试已开始，真实 PG18 数据副本、对应 DBS 二进制和四个 CCG 实际运行；48 小时连续采样和两轮 03:00 全量备份仍在进行中，不能提前标记通过。原环境为 PG14、128 GiB 容器上限且依赖集群服务，94 为 PG18 和更小节点，差异必须列入结果。

## 2026-11-07：当前交付范围调整

用户决定暂不生成新版说明视频，也暂不制作给领导的长期方案；只有收到后续明确通知才重新安排。旧候选版已发布的视频和历史文件保留，不能代表当前48小时试验的最终结论。四容器实测、每12小时图表、实时Web、源码、二进制和使用文档继续进行。

隔离实验初次尝试用节点IP直接访问Web失败：页面默认只绑定Pod内回环地址，节点没有转发端口。实验已增加仅绑定测试节点内网地址的四路临时转发，并在保持observe动作时让四处实际进程使用修复时钟误报的rc.2；页面和状态API从客户端均返回200，四Pod无重启。正式部署的访问控制与端口方案见[四容器部署说明](FOUR-CONTAINERS.zh.md)。
