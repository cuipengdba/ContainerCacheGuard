# v0.2.0 rc7 新目录发现与状态解释

这是候选版本。它修复已知行为并补充回归，不代表真实四容器业务、等强度压力或48小时稳定性验收通过。程序仍只治理普通磁盘文件页，不能释放PostgreSQL查询匿名内存、shared_buffers或Redis数据。

## 本次解决的具体问题

旧备份目录包含大量文件时，普通目录遍历可能用完当前发现额度。此前新建目录或文件的inotify提示在额度不足时会被跳过，只能等后续补扫。新版本将总发现速率中的25%留给事件发现，75%用于普通遍历，并把已收到但暂时没有额度的提示放入有界FIFO队列，稍后重试。未启用或无法使用inotify时，普通遍历使用全部发现速率。

队列去重，上限与`max_hint_files`相同；等待至少60秒或更长的既有保护窗口后到期清理。重试仍重新检查权限、符号链接、文件类型、支持的文件系统与设备号，不绕过写入保护、回收预算或业务退让。内核事件丢失、watch上限及队列溢出仍可能延迟覆盖，普通补扫不能取消。

新增状态计数：

| 字段 | 含义 |
| --- | --- |
| `counters.pending_hint_paths` | 已收到提示、等待发现额度的路径数，不代表正在回收的文件数 |
| `counters.hint_discovery_retries` | 从等待队列取出后重新尝试发现的次数，不保证文件仍存在或能被索引 |
| `counters.hint_queue_dropped` | 等待队列满或提示到期的累计丢弃次数；之后依赖补扫 |

## 页面和监控更容易解释

状态新增`diagnostics`，网页增加“当前判断与建议”。它解释普通文件页软目标、非普通文件页用量和当前是否允许建议；当可见组高水位与非普通文件页占多数同时出现时，提示检查业务查询、共享内存和容量。这里的构成观察不等于根因判定，也不新增任何自动杀进程、改cgroup或清应用缓存的操作。

`other_charged_bytes = max(current_bytes - max(file_bytes-shmem_bytes,0),0)`，是当前计费用量扣除普通文件页后的近似剩余。它包含多种类型，并不是一种可以直接清空的“其它缓存”；指标读取时刻不同也可能产生小幅不一致。

文件页refault新增`file_refaults_available`和`file_refault_rate_valid`。首次采样、字段缺失、计数回退或前一采样失败时，速率显示“未知”。启用`max_file_refaults_per_second`保护后，没有有效差分基线时暂停新释放，待连续有效采样恢复。不能再把未知数据当成零重读。

网页曲线按真实时间间隔绘制；采集错误和长空窗断线，错误期间的卡片显示未知。cgroup v1未采集的slab也显示未知。浏览器刷新仍只读取有界状态，不触发目录扫描。

## 升级和验证

配置格式兼容原版本，无需新增必填参数；新计数与诊断字段为追加。开启事件发现时，普通遍历速率占比改变，应重新测量目录覆盖时间。使用refault保护的用户会在初始基线未建立时看到短暂暂停，这是有意的保守行为。

先运行`doctor`，在独立状态目录用`observe`核对范围和指标，再逐范围验证`enforce`。保留旧程序和配置以便回退。不要把替换CCG理解为已修复业务巨型SQL或已消除节点容量不足。

测试覆盖：原生Linux amd64与arm64执行`go vet`、race单元测试、真实文件CLI回归、静态ELF依赖检查，以及内嵌网页行为检查。新增回归覆盖额度耗尽后的新目录和文件、队列去重/上限/过期、等待期间被替换成符号链接、refault未知/计数回退及图表空窗。各项最终结果以对应GitHub Actions记录为准；未进行原生ARM 64KiB页和本版本真实数据完整备份长稳验收。

机制参考：[Linux inotify手册](https://man7.org/linux/man-pages/man7/inotify.7.html)、[Linux cgroup v2文档](https://docs.kernel.org/admin-guide/cgroup-v2.html)。
