# 测试报告

更新：2026-11-06。当前为候选版验证过程，测试结果随实际完成更新；未完成项不会算通过。

## 已完成的机制验证

- 在 Linux 5.14 x86_64 实机运行新项目的 Go 测试通过：策略安全分支、同 UID 文件释放及 SHA256 不变、父路径/末级 symlink 拒绝、FIFO 类型拒绝、截断/替换身份变化、状态目录权限和重复进程锁、自动发现/排除、过期业务信号、索引上限及观察模式不建议、对齐和速率额度。
- amd64 静态 ELF 检查通过；arm64 已交叉编译，原生执行以 CI 后续结果为准。
- 上述只证明对应测试条件，不等于真实业务性能或驱逐验收通过。

## CI 证据纠错记录

CI 42167925413、42169423730 的工作流曾显示 success，但下载逐项日志发现权限单测失败：测试目录权限没有显式设置为0700，runner默认权限与测试假设不同；同时 `go test | tee` 的管道没有强制传递测试失败。两次运行**不能计为整套通过**。保留原始记录；静态检查和独立CLI集成结果分别有效。已修复测试夹具，并为CI显式启用 bash 与 pipefail，等待新运行核验。产品的私有状态目录权限要求没有放宽。

## 真实数据实验

使用事先完整迁移、升级并审计一致的 PG18.6 数据副本：约198GiB、1428个业务模式、10217个业务物理表/分块、642157127行。新实验另外建立 reflink 副本，保留原审计基准。

测试采用独立 PostgreSQL 容器与备份/治理容器，数据库12GiB、工作容器6GiB限制。使用原生 pg_basebackup、相同96MiB/s吞吐限制、只读查询探针，分别记录源端和目标端 cgroup、驻留、IO、时间、查询延迟及 OOM 事件。

当前无治理全量备份基线进行中；开启 CCG 的对应对照尚未完成。备份结束驻留测量与后续 pg_verifybackup 分阶段记录，避免校验读取混入备份过程指标。冷起始条件只对独立实验副本发出文件建议，不执行全机 drop_caches。

这里复用的是真实迁移 hisdbs 数据，DBS 的备份/同步访问形态由实验模拟；没有宣称已运行完整 DBS 业务二进制，也没有独立迁移另一份 DBS 数据。该实验不是生产负载重放。
