# ContainerCacheGuard 0.2.0-rc.17 候选版

新增**默认关闭**的memory.reclaim后端，用于在内存风险提前显现时请求一次整个容器cgroup的内核主动回收。普通文件后端和旧配置继续兼容，无Web/HTTP服务，仍提供静态amd64/arm64程序及每日详细日志。

- 真实cgroup2、叶子目标、设备/inode/启动身份和SO_PEERCRED核对；只接受已登记目标，拒绝客户端自报路径和回收量。
- 分别检查容器、有限父级和来源绑定的实际kubelet节点/allocatable信号；不把宿主MemAvailable当成kubelet驱逐信号。
- 每个压力事件至多一次尝试；先持久登记、后执行。失败、EAGAIN、EINTR、短写不自动重试；重启时未决结果UNKNOWN继续阻止重复执行。
- 固定节点锁、一个在途辅助进程、备份目标优先；30秒最短节点间隔、5分钟1GiB请求预算。文件工作线程先停让并确认，两个后端不并发操作同一目标。
- 辅助进程隔离阻塞写入，看门狗发起终止但不假定能打断内核IO；保持串行占用至真实退出。
- 1/5/30/120秒复查记录实际时间、内存类别、IO/refault/业务指标与节点信号；请求量、容器下降和驱逐余量分别核对。
- 历史OOM不因重启自动清除；默认要求禁用swap、有效PSI、真实业务覆盖和IO保护。无PSI仅有显式实验策略，单次≤128MiB且要求真实磁盘替代信号。

[完整中文配置、参数、四容器接入与回退](RC17-USAGE.zh.md)。源码中的`internal-kernel-write`仅供受控继承FD调用，没有作为公开绕过保护的命令。节点执行器读取宿主PID/cgroup视图，业务容器无需开放cgroup写权限；OpenShift/SCC/SELinux、具体运行时及生产schema2采集器需另行接入验证。

**范围扩大必须明确接受。** memory.reclaim覆盖整个登记cgroup，文件路径和WAL排除规则不适用于这次内核操作。内核可多回收、少回收或引起业务重读/IO；不承诺主动回收anon、shmem、slab。已被kubelet扣除的inactive_file下降，未必改善驱逐余量。单次512MiB默认上限及其他门槛是候选起点，不是已标定的生产安全值。

**现场验收仍未通过。** 本轮只读确认94运行5.14内核/cgroup2，接口存在、PSI缺失；没有改94现有业务，没有连接或修改171。真实DBS/HISDBS四角色匹配压力、完整备份恢复、无PSI物理盘关联、Kubernetes驱逐对照和48小时长稳仍需独立完成。内置接口完成和隔离缓存下降不能写成“已保证永不驱逐”。
